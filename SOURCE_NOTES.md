# Источники и адаптация NexGAP

MVP написан самостоятельно на основе изученных подходов NexGAP. Исходный архив и большие датасеты хранятся отдельно от репозитория, не изменены и не нужны для запуска. Код MVP не импортирует и не исполняет исходники архива. Область реализации ограничена тремя фиксированными семействами задач на CSV и SQLite; полный пайплайн NexForge здесь не воспроизводится.

Origin и коммит проверены по локальной Git-истории; основные прочитанные файлы побайтно совпали с этим снимком. ## Потоковая проверка формата датасетов

Метаданные архива фиксируют ревизию датасета `d8d4de5643f9fe9d3fc3f89b3d55b8709ddc35c9`. Из [tool_calling.jsonl](https://huggingface.co/datasets/nex-agi/agent-sft/blob/d8d4de5643f9fe9d3fc3f89b3d55b8709ddc35c9/tool_calling.jsonl) и [agent.jsonl](https://huggingface.co/datasets/nex-agi/agent-sft/blob/d8d4de5643f9fe9d3fc3f89b3d55b8709ddc35c9/agent.jsonl) прочитаны только первые **5 записей каждого файла**, по одной строке. Наблюдаемые типы полей и структуры сообщений без исходных формулировок и значений сохранены в [reference-format.json](reference-format.json). Это описание небольшой выборки, а не утверждение обо всех записях датасетов.

В выборке `tool_calling.jsonl` верхний объект содержит `messages`, `tools`, `uuid`, `generator`; у сообщений есть строковый `content` и список `tool_calls`, в том числе пустой. Ответ инструмента связан с вызовом через `tool_call_id`, а `function.arguments` хранится строкой JSON. Выборка `agent.jsonl` показывает текстовые диалоги без отдельных сообщений роли `tool`; её формат не используется как целевой для инструментальных траекторий.

[export.py](synthetic_agent_pipeline/export.py), функция `serialize_record`, приводит копию API-диалога к наблюдаемому формату: добавляет пустые `tool_calls`, заменяет `content: null` на пустую строку, добавляет стабильный `uuid` и собственный `generator`. Исходные API-сообщения в трассах сохраняются. Аргументы функций остаются JSON-строками. Валидатор проверяет однозначность `tool_call_id`, завершённость всех вызовов и соответствие имени инструмента, если оно указано в ответе.

[sources.py](synthetic_agent_pipeline/sources.py) при наличии внешнего архива выполняет дополнительный ограниченный аудит и сравнивает сериализацию экспорта с первыми двумя эталонными строками `tool_calling.jsonl`. Эти проверки не оценивают качество решений учителя. Исходные задачи из датасетов не копируются в сгенерированные входные данные, обучающий экспорт или запросы учителю.

## Отличия MVP

- В Gyrfalcon формулировки создаёт LLM, persona выбирается случайно, а дерево типов может расширяться. Здесь три фиксированных семейства и шаблоны; seed определяет входные записи, а декларативное расписание чередует типы и сложности. Это позволяет воспроизвести и проверить задания без API.
- В MVP эталоны строятся непосредственно из записей генератора на Python и хранятся отдельно от агентских данных. Принимает решение строгий детерминированный тест, а не модель-судья.
- Вместо NexA4A и Langfuse используется один агент с пятью локальными инструментами, собственные JSONL-трассы и отдельный процесс на задачу с лимитом шагов и общим тайм-аутом.
- Преобразователь поддерживает нативные JSON function calls. Он отклоняет смешанные задачи, несовместимые истории и повреждённые вызовы; не восстанавливает отсутствующие идентификаторы и не подменяет некорректные аргументы пустым объектом. XML-стили вызовов из других конвертеров NexGAP не реализованы.
- Полное семейство `sales_summary` выделяется в validation. Mock-экспорты хранятся отдельно от реальных траекторий учителя и служат только для проверки пайплайна.

В заголовках изученных исходников NexGAP указан Apache-2.0. Код MVP написан самостоятельно: адаптированы организация генерации, поля экспорта и принцип преобразования трасс. Исходный код не включён в пакет, не скопирован в реализацию и не используется как runtime-зависимость; скачанный архив остаётся отдельным набором материалов.
