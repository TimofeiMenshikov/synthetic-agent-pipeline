## Что проверено

Все 52 автоматических теста прошли без ошибок при наличии внешнего архива. Без него тест потокового чтения исходного датасета автоматически пропускается; остальные тесты запускаются самостоятельно. Команда из корня клонированного репозитория:

```sh
python3 -W error::ResourceWarning -m unittest discover -s tests -v
```

Полный вывод: [verification-tests.txt](verification-tests.txt). Машиночитаемый итог: [verification-summary.json](verification-summary.json).

Проверены воспроизводимость 20 заданий, строгая отбраковка неверных результатов, ограничения файловых инструментов и SQL, остановка дочернего процесса по тайм-ауту, лимит шагов, полный путь через HTTP, обработка ошибок API и отсутствие ключа в артефактах. Дополнительно проверены потоковая выборка локальных датасетов, совпадение формата с `tool_calling.jsonl` и преобразование последнего generation snapshot без дублирования истории. Тесты экспорта покрывают одиночные и параллельные вызовы, пропущенные ответы, чужие и повторные `tool_call_id`, неправильный JSON и исключение отклонённых траекторий.

Оба итоговых `train.jsonl` и `validation.jsonl` заново прочитаны после финальных изменений валидатора. Каждая строка содержит `messages`, `tools`, `uuid`, `generator`, строковый `content` и массив `tool_calls` у каждого сообщения; ответы инструментов связаны с вызовами через `tool_call_id`. Набор экспортированных task_id точно совпал с набором принятых задач. Mock-артефакты сохранены только внутри `artifacts/mock/`; каталога реальных обучающих траекторий `artifacts/teacher/` нет.

Деревья сгенерированных файлов, включая CSV, SQLite, метаданные и отдельные эталоны, совпали побайтно между прогонами. Общий SHA-256:

```text
dc022c32bd89b1460e286922788c8e94b9dc5d446f6a0f32c691607153d5b7ae
```

Побайтная гарантия проверена на текущих версиях Python и SQLite; версии записаны в `verification-summary.json`. Эталоны находятся вне каталогов агента, mock вычисляет решение только по ответам инструментов. Эти mock-записи предназначены для проверки пайплайна и не являются данными для SFT.

## Локальные результаты и воспроизведение

Полные артефакты прогонов исключены из Git. В репозитории сохранены этот отчёт, [verification-summary.json](verification-summary.json) и [verification-tests.txt](verification-tests.txt); входные файлы, трассы и JSONL можно заново получить командами ниже.

- Обычный прогон: `artifacts/mock/nex20-clean/report.json`, `artifacts/mock/nex20-clean/exports/train.jsonl`, `artifacts/mock/nex20-clean/exports/validation.jsonl`.
- Прогон с неверными ответами: `artifacts/mock/nex20-reject/report.json`, `artifacts/mock/nex20-reject/results.jsonl`.
- Полные вызовы инструментов, ответы и диалоги: `artifacts/mock/<run-id>/traces/<task-id>/`.

Воспроизведение из корня проекта после клонирования:

```sh
python3 -m synthetic_agent_pipeline run --mode mock --count 20 --seed 20261117 --run-id nex20-clean
python3 -m synthetic_agent_pipeline run --mode mock --count 20 --seed 20261117 --mock-fail-every 5 --run-id nex20-reject
python3 -m synthetic_agent_pipeline check-jsonl artifacts/mock/nex20-reject/exports/train.jsonl
python3 -m synthetic_agent_pipeline check-jsonl artifacts/mock/nex20-reject/exports/validation.jsonl
```

Если имя прогона уже занято, укажи новый `--run-id`. Внешний архив для этих команд не обязателен; при его наличии можно добавить `--archive` с путём к нему для дополнительной проверки исходного формата.

## Запуск модели-учителя

После установки реальных значений переменных окружения:

```sh
export TEACHER_API_KEY='YOUR_API_KEY'
export TEACHER_BASE_URL='https://api.openai.com/v1'
export TEACHER_MODEL='YOUR_TOOL_CALLING_MODEL'
python3 -m synthetic_agent_pipeline run \
  --mode teacher --count 20 --seed 20261117 \
  --run-id teacher20 --max-steps 16 --timeout 120
```

Результат будет в `artifacts/teacher/teacher20/`. Экспортируются только траектории, прошедшие детерминированную проверку; число принятых решений реальной модели заранее неизвестно. Другой OpenAI-совместимый endpoint задаётся через `TEACHER_BASE_URL`.

## Изученные локальные материалы

Архив использовался как внешний набор источников и не включён в репозиторий. В скачанный код правки не вносились; размеры и хеши прочитанных префиксов 24 выбранных файлов не изменились, см. [archive-preservation.json](archive-preservation.json).

Прочитаны Gyrfalcon pipeline, примеры frameworks и QueryExporter, NexGAP runner и trace converters. В самостоятельной реализации MVP адаптированы декларативные framework/persona/дерево типов/сложность, отдельный `queries.jsonl` и подход к преобразованию последнего generation с полной историей. Генератор ограничен тремя фиксированными семействами и детерминированными шаблонами; полный пайплайн NexForge здесь не воспроизводится. Конкретные ссылки и отличия перечислены в [SOURCE_NOTES.md](SOURCE_NOTES.md). Наш код не импортирует и не исполняет исходники архива.

Первые 5 записей каждого `tool_calling.jsonl` и `agent.jsonl` изучены потоково, без загрузки датасетов целиком. Структурное резюме без текста чужих задач: [reference-format.json](reference-format.json). Формат всех строк новых экспортов проверен против соглашений локального образца: `uuid`/`generator`, `tool_calls: []` без вызовов, строковый `content`, строковые JSON-аргументы и связь ответов через ID. Локальный результат автоматического сравнения сохранён в `artifacts/mock/nex20-clean/reference_compatibility.json`; для повторения этой дополнительной проверки нужен внешний архив.

Сравнение касается структуры изученной выборки, а не всего исходного датасета. Для обучения конкретной модели остаётся проверить настройки её тренера. Проверки mock и локального HTTP не измеряют качество реального учителя.
